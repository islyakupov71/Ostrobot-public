# ОСТРО

Telegram-бот и Mini App для управления задачами, дедлайнами и отчётностью команды.

Задача появляется в рабочей системе → бот сообщает сотруднику → сотрудник подтверждает
получение → бот следит за сроком → руководитель видит, где просрочки и где нужна реакция.

---

## Как это устроено

Источник правды — **PostgreSQL**. Google-таблица остаётся живым рабочим листом,
с которым команда работает как привыкла, и синхронизируется в обе стороны.

```
                    ┌──────────────────┐
   Telegram ────────►                  │
   (бот + Mini App) │   API (Fastify)  ├────► PostgreSQL ◄──── источник правды
                    │   бот (grammY)   │        ▲  │
                    └──────────────────┘        │  │
                                                │  │
                    ┌──────────────────┐        │  │
                    │  Worker          ├────────┘  │
                    │  pg-boss         │           │
                    │  напоминания     ◄───────────┘
                    │  синк, сводки    │
                    └────────┬─────────┘
                             │  batch write / poll
                             ▼
                    ┌──────────────────┐
                    │  Google Sheets   │ ◄──── здесь работают люди
                    └────────┬─────────┘
                             │ Apps Script onEdit
                             └──────────► /hooks/sheets
```

**Почему не только таблица.** Sheets не даёт транзакций, режет по 60 запросов
в минуту и заставляет планировщик вычитывать весь лист на каждом цикле. Бот на такой
основе тормозит, теряет правки при одновременном редактировании и молча замолкает
при исчерпании квоты. Postgres снимает всё это, а двусторонний синк сохраняет
таблицу как рабочий инструмент — буква ТЗ соблюдена, надёжность не принесена в жертву.

**Почему без Redis.** Очередь отложенных заданий живёт в том же Postgres через
`pg-boss`. Для команды до двадцати человек отдельный Redis — это лишний сервис,
который надо поднимать, мониторить и чинить, ради возможностей, которые не нужны.

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Бот | grammY | Типы из коробки, аккуратная работа с webhook |
| API | Fastify + Zod | Схемы валидации те же, из которых фронт берёт типы |
| База | PostgreSQL + Drizzle | Явные миграции, читаемый SQL, частичные индексы |
| Очередь | pg-boss | Отложенные задания и cron внутри Postgres |
| Mini App | React 19 + Vite + Tailwind v4 | Собственная дизайн-система, без готовых китов |
| Таблицы | Google Sheets API v4 | Батчинг записи, откат при 429 |
| Прод | Docker Compose + Caddy | Автоматический TLS, воспроизводимый деплой |

## Структура

```
ostro/
├── apps/
│   ├── api/          HTTP + Telegram-бот в одном процессе
│   │   ├── auth/     проверка подписи initData, JWT-сессии
│   │   ├── bot/      сценарии, клавиатуры, тексты
│   │   └── routes/   REST для Mini App, вебхуки
│   ├── worker/       напоминания, синк с таблицей, сводки
│   └── web/          Mini App
│       └── design/   дизайн-система
├── packages/
│   ├── shared/       enum'ы, Zod-контракты, русские подписи
│   ├── core/         машина состояний, правила напоминаний, права
│   ├── db/           схема Drizzle и миграции
│   └── sheets/       двусторонняя синхронизация
├── infra/
│   ├── apps-script/  скрипт для Google-таблицы
│   └── deploy/       Dockerfile, Caddyfile
└── docs/
```

Доменная логика живёт в `packages/core` и не знает ни про Telegram, ни про HTTP,
ни про базу. Статус задачи меняется из четырёх мест — кнопка в чате, карточка
в приложении, правка строки в таблице, автоматика планировщика — и правила
перехода должны быть у всех одни.

## Быстрый старт

Нужны Node 22+, pnpm и PostgreSQL 16+.

```bash
pnpm install
cp .env.example .env      # заполни токен бота, DATABASE_URL и JWT_SECRET
pnpm db:generate          # сгенерировать миграции из схемы
pnpm db:migrate           # применить их
pnpm dev                  # API, воркер и Mini App разом
```

Без `TELEGRAM_WEBHOOK_URL` бот работает в режиме long polling — публичный адрес
для разработки не нужен. Mini App при этом открывается на http://localhost:5173
как обычная страница: SDK Telegram определяет своё отсутствие и включает
светлую тему по системным настройкам.

Подробный разбор с получением токена, доступа к Google и настройкой домена —
в [docs/SETUP.md](docs/SETUP.md).
